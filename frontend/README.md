# RMS Platform — Frontend

Веб-интерфейс системы управления сервисными роботами: мониторинг парка, управление задачами, карты этажей и аналитика.

Общая инструкция запуска проекта находится в [README репозитория](../README.md). Здесь описана только клиентская часть.

## Технологии

- React 19, JavaScript (JSX).
- Vite 8 — разработка и сборка.
- React Router 7 — маршрутизация.
- Lucide React — иконки; Recharts — графики.
- CSS — оформление интерфейса; ESLint — проверка кода.

## Запуск frontend

Рекомендуемая версия Node.js — 24 LTS. Из корня репозитория выполните:

```bash
cd frontend
npm ci
npm run dev
```

Интерфейс доступен по адресу http://localhost:5173. Для работы с данными необходим доступ к RMS API. Его запуск описан в [документации backend](../backend/README.md).

| Команда | Назначение |
| --- | --- |
| `npm ci` | Установка зависимостей из `package-lock.json` |
| `npm run dev` | Запуск сервера разработки |
| `npm run lint` | Проверка кода ESLint |
| `npm run build` | Production-сборка в `dist/` |
| `npm run preview` | Локальный просмотр собранного приложения |

## Конфигурация

Адреса подключения определены в `src/shared/config/api.js`. Для локального запуска используются значения по умолчанию:

| Переменная | Значение | Назначение |
| --- | --- | --- |
| `VITE_API_BASE_URL` | `http://127.0.0.1:8000` | Базовый адрес REST API |
| `VITE_WS_URL` | `ws://127.0.0.1:8000/ws` | Адрес WebSocket |

При необходимости скопируйте `.env.example` в `.env.local`, измените значения и перезапустите Vite. Если `VITE_WS_URL` не указан, он формируется из базового адреса API.

Переменные `VITE_*` доступны в браузере. Не храните в них секреты, пароли или ключи устройств.

## Архитектура

Используется упрощённый Feature-Sliced Design (FSD). Код разделён по ответственности слоёв и предметных модулей.

```text
src/
├── main.jsx                 # Точка входа React
├── app/
│   ├── App.jsx              # Состояние и инициализация приложения
│   ├── router/              # Маршруты и перенаправления
│   └── styles/              # Глобальные стили
├── pages/                   # Страницы
│   └── <page>/
│       ├── ui/              # Компоненты страницы
│       └── index.js         # Публичный интерфейс
├── widgets/
│   └── app-layout/          # Каркас приложения
├── entities/
│   ├── robot/               # Статусы роботов
│   ├── task/                # Статусы задач
│   └── event/               # Демонстрационные события
└── shared/
    ├── config/              # Конфигурация подключения
    └── ui/                  # Общие UI-компоненты
```

### Ответственность слоёв

| Слой | Назначение |
| --- | --- |
| `app` | Инициализация приложения, маршрутизация и глобальные стили |
| `pages` | Композиция интерфейса отдельных страниц |
| `widgets` | Самостоятельные крупные блоки интерфейса |
| `entities` | Модели и компоненты предметной области |
| `shared` | Переиспользуемые компоненты и инфраструктурные инструменты |

Зависимости направлены сверху вниз:

```text
app → pages → widgets → entities → shared
```

Разрешены импорты через несколько слоёв вниз. Обратные зависимости и прямые зависимости между независимыми срезами одного слоя не допускаются. Слой `features` будет добавлен при выделении пользовательских сценариев; сейчас он отсутствует.

### Публичные интерфейсы

Внешние модули используют `index.js` среза. Внутри среза применяются прямые относительные импорты. Публичный интерфейс экспортирует только то, что необходимо другим модулям.

Пример импорта из компонента страницы (`pages/*/ui/`):

```jsx
import { Badge, PageHeading } from '../../../shared/ui/index.js'
```

Не используйте `export *` без необходимости и не создавайте `index.js` в каждой вложенной папке.

### Стили

Глобальные стили подключаются в `main.jsx` через `app/styles/index.css`. CSS разделён по разделам интерфейса. При изменении порядка импортов необходимо учитывать каскад. Стили на текущем этапе глобальные, CSS Modules не используются.


## Текущие ограничения

- Авторизация и часть интерфейсов работают в демонстрационном режиме.
- Карта этажей пока использует демонстрационные схемы и позиции роботов.
- REST-запросы и WebSocket используют существующий контракт RMS API. Единый API-клиент и механизм переподключения пока не выделены.
- TypeScript, автоматические тесты и автоматическая проверка архитектурных границ пока не настроены.
